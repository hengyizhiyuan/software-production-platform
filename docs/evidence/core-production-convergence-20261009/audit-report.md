## A. Executive Verdict

### What is proven, and what is not

Watt has real, reusable production and governance capability. Historical P0/P1 receipts establish a **scoped single-ECS static-software path**, including a real single-PWU Candidate, Human Acceptance V1, real Multi-PWU production using that exact V1, verified join, Acceptance V2, exact Git/SQL source promotion and bounded recovery. Those passes remain valid at their recorded revision. They do not establish arbitrary requirement, arbitrary topology or current N1/GOF qualification.

**Generic, sustainable governed convergence is currently not proven.** Three different problems must remain separate:

1. **Confirmed contract defects:** the latest N1 IR-Constraint route is not transported by one Steering Completion Contract path; its result shape is not consumed by a Fact-only protected-context consumer; Guardian's new evidence path compares an input baseline to a Candidate output revision. Current Watt + current ECF main also have an incompatible managed-context API despite both accepting nominal version 0.1. These are conditional, source-confirmed edges, not causes retrospectively assigned to the last failed G0.
2. **Missing complete capability:** admitted Fact/Constraint → legal Owner/phase/evidence/Gate binding is only partially implemented. The new bindings and exact negative gates are useful; raw lexical routing and protocol-specific routes do not establish complete governed handling for unlisted lawful requirements. Existing local Self-Refine does not itself discharge every Work obligation or create missing authority.
3. **Missing qualification / historical diagnostics:** latest recovery `9b3ca2f` has no new image or full Work; four recorded GOF G0 trials had zero Candidate/Verification at retained observations; three have recorded UNABLE_TO_COMPLETE, while the first terminal outcome is UNKNOWN. Workspace diagnostics do not identify the failed predicate/errno. Real unrecoverable Context Assembly truthful-stop, broad expression holdouts and recovered-to-final-Work evidence remain absent for the new capability.

A broad core-function expansion cannot use the current evidence as a general platform qualification. Architecture Lead/Human Governor should first review the bounded complete engineering units in section F. This is an audit recommendation, not a new Runtime gate or authorization to implement them.

## C. ADR-0002 Conformance Findings

### C1. Lawful determinism — retain

Exact Git commit/tree/diff, schema/reference validation, immutable Work/Fact provenance, version/CAS, capability grants, resource budgets, source witnesses, permit/effect integrity, Candidate fingerprint, independent Guardian and explicit Human gates perform deterministic governance. Enum presence, method names or a finite tool protocol do not themselves substitute for intelligent semantic judgment.

Examples at M: [Verification exact result/basis checks](https://github.com/hengyizhiyuan/software-production-platform/blob/3c367be19d7663b5b9764347b45e6ae355c28e7d/src/spg/application/verification.py#L157), [Task protected-context validation](https://github.com/hengyizhiyuan/software-production-platform/blob/3c367be19d7663b5b9764347b45e6ae355c28e7d/src/spg/domain/production_intelligence.py#L397), Native binding validation and later produced-vs-verified distinction in the execution note. N typed PROHIBIT_DEPLOY/PUBLISH routes identify actual capabilities; they are not automatically Subject aliases.

### C2. Lawful stochastic candidate boundaries — implemented, generality bounded by evidence

WIC model Candidates receive original-basis validation/error feedback and bounded repair. Semantic-step candidates are validated before admission. Native inference proposes tools/completion under grants/budgets. N post-admission materialization can use a bounded model-generated check plan while preserving original Fact identity/value/order/scope/provenance/authority; a wrong Candidate still fails.

[N StaticHTMLPlanRepair](https://github.com/hengyizhiyuan/software-production-platform/blob/5fd2579f8ab67db12f6ea122048613184276175f/src/spg/providers/static_html_semantic_verifier.py#L460) has at most two candidate attempts, exact source/target/value validation and explicit unverifiability. This is a useful existing mechanism, not a general approved-test-program generator. Its retained scripted plan-repair tests prove mechanics, not full live unlisted-requirement convergence. WIC refinement is not evidence that a separate absent generic fulfillment-mapping refinement exists.
