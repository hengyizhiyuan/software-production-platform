## Confirmed implementation boundaries

### Primary context

`existing-primary-contribution-background-v1` is explicit and request-bound. With no marker, the previous source eligibility rules remain. Under the new marker, empty effects and shared governed provenance no longer automatically exclude a candidate for the existing conditional background review path. Primary current Fact contribution, negative polarity, action, Human requirement and effects outside the existing Production Intent domain still prevent eligibility.

The marker is passed into Owner prerequisite projection, Admission, feedback, dependency observations and the actual whole-background consumer. All current Facts still need non-Context/non-UNRESOLVED routes; a same-Item actual current production request remains required. Eligibility does not determine whether an open-language source is descriptive.

Final v3 Admission requires independent component Review. The normal RepositoryCodeVerifier calls `validate_continuous_gates`, which revalidates the complete projection, original Wire, Inventory, Attempt and persisted Review chain before verification consumers execute. No confirmed normal-pipeline Review bypass was found. Direct helper eligibility and mock verdicts are not substitute qualification of that actual chain.

### Lossless Wire presentation

`existing-lossless-json-frame-v1` retains the entire original Provider output in `MODEL_RESPONSE_OBSERVED`. Its pure extractor recognizes a complete outer JSON fence and records raw SHA/UTF-8 size, inner character and byte ranges, and inner SHA/size. `_wire_response_basis` independently recomputes and compares that presentation metadata. Original attempt/request/response/parent identities are retained.

The extractor does not invent characters, repair spans, choose a JSON value from prose, or accept incomplete internal JSON. Actual strict JSON/duplicate-key/schema/h/d/source/Owner/authority/Review gates still apply to the derived body. Legacy requests with no marker still reject fenced outputs; old replay is not upgraded.

New test definitions cover original UTF-8 geometry, plain/fenced equivalence, raw receipt retention, replay presentation drift, schema/source/header failures, duplicate keys, multiple values/fences, prose and truncation. These definitions were read, not executed by this reviewer.

### Model Runtime terminal output

The stream loop ends after an observed terminal event containing a response object, then applies the existing status and usage checks. Completed terminal text may supply only the Provider's exact continuation of an already observed delta prefix. Conflicting or shorter terminal text becomes non-retryable `STREAM_TERMINAL_OUTPUT_MISMATCH`; it is not substituted as a repaired Candidate. Terminal-only and delta-only observations are identified separately.

Successful output evidence records only safe status, selection, byte counts and SHA256 values. Formation/Review observations retain it through the existing Model Runtime Owner. Existing timeout, transport recovery and logical request budgets are unchanged. Tests specify no EOF wait after terminal, exact-prefix completion and conflicting/truncated terminal rejection.

This repairs confirmed current code behavior. Ordinary47 Formation1's full terminal text was not retained; its historical truncation cause remains UNKNOWN. Current tests or a later successful response cannot reconstruct that missing historical value.

## Generic source-union regressions

These are ordinary, controlled contract examples. They must not use Holdout input or become source IDs, subjects, keyword branches or production prompts. A mock review's expected false verdict tests Owner rejection of that verdict; it does not prove a real model can identify the semantic error.

| Generic case | Invalid submission | Required protection |
|---|---|---|
| One source combines distinct continuous prohibited operations and a forbidden change boundary | Routes deny the two operations but omit the change-scope consumer; another source happens to contain Git | The original source's own consumer union remains incomplete.
