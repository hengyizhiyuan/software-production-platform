# 奥特曼塔防 H5 小游戏 · 设计方案（待评审，暂未实施）

> 状态：**设计方案 / 待 Human 评审**。本文档是第一版可玩版本的设计方案，尚未实现任何游戏代码。
> 依据 Human 原始需求：做一个简版的 H5 塔防小游戏，题材是奥特曼打怪兽，类似植物大战僵尸，但是地图不需要那种棋盘格。

---

## 1. 目标与范围

### 1.1 目标
做一个**简版、可直接在浏览器中打开即玩**的 H5 塔防小游戏：玩家扮演守护地球的奥特曼阵营，在一条非网格化的战场通道上布置防守单位，阻挡并消灭一波波来袭的怪兽。

### 1.2 本方案包含的内容
- 非棋盘格的地图与路径表现
- 奥特曼打怪兽的题材包装
- 类《植物大战僵尸》的放置、产出、攻击、波次玩法
- 胜负条件与操作方式
- 第一版可玩版本（MVP）的实现拆分

### 1.3 明确排除的内容
- **棋盘格 / 网格瓦片式地图布局**（Human 明确要求排除）
- 账号、排行榜、内购、联网对战等非本期内容
- 未经评审即开始写游戏代码（本步骤只交付方案）

## 2. 题材：奥特曼打怪兽

### 2.1 阵营
| 阵营 | 角色定位 | 说明 |
| --- | --- | --- |
| 防卫方（玩家） | 奥特曼 / 地球防卫队 | 玩家布置的防守单位，站在战场通道的守卫侧，不移动 |
| 进攻方（敌方） | 怪兽 | 从战场一侧成波次沿通道向基地推进 |

### 2.2 题材表现（美术策略）
- 第一版采用**纯代码绘制的简化造型**（Canvas 2D 圆形 / 多边形 + 配色 + 发光特效），不依赖任何外部素材文件，保证 H5 单页直接可玩。
- 奥特曼一侧使用银红主色 + 胸口计时器灯；怪兽一侧使用暗色 + 尖角造型。
- 计时器灯可以在战斗后期闪烁，作为氛围反馈（纯表现，不改变规则）。
- 所有角色名与造型均为**原创简化形象**，不使用受版权保护的影视素材。

## 3. 地图与路径表现（非棋盘格）

### 3.1 核心原则
地图**不是**由等距方格 / 瓦片拼成的棋盘，而是**一条（或数条）连续的道路通道 + 不规则的防御带**。玩家看到的是「一条从远处通向基地的路」，而不是一格一格的棋盘。

### 3.2 具体设计
- **通道（Lane）**：3 条左右走向的**连续曲线通道**（贝塞尔曲线生成），每条通道有自己的宽度与轻微起伏；通道之间用岩石、树木、废墟等背景装饰分隔，而不是网格线。
- **无格线**：不绘制任何方格线、格点、瓦片贴图；通道与地面的边界用柔和的边缘、路面色差和阴影表现。
- **防御带（Placement Zone）**：通道旁侧有一条连续的「可布防地带」，视觉上是一条带状区域（例如沙地 / 平台边缘），不是格子。
- **落点吸附**：玩家在防御带上点击时，落点会被**吸附到该通道的「布防槽位」**（每个槽位是一个沿通道曲线排布的坐标点，槽位之间距离不等、位置随曲线弯曲），以保证防守单位始终站在合理的位置与朝向；这是**沿曲线的锚点集合**，不是网格。
- **怪兽行进**：怪兽沿通道中心曲线按固定速度前进，位置由曲线参数 `t`（0→1）决定，整体呈连续滑动，而非格与格之间跳动。

### 3.3 为什么满足「非棋盘格」
| 棋盘格地图（被排除） | 本方案 |
| --- | --- |
| 等距方格铺满整屏 | 曲线通道 + 连续装饰地面 |
| 单位按 (row, col) 对齐 | 单位按曲线上的槽位锚点对齐 |
| 敌我占格、格子互斥 | 无格子概念，仅判断槽位是否已被占用 |
| 网格线 / 瓦片贴图 | 无任何格线，用美术分层表达区域 |

## 4. 玩法：类《植物大战僵尸》的防线机制

### 4.1 资源：光能（Energy）
- 顶部显示当前光能，光能是唯一的建造资源。
- 光能由**光能核心**类单位周期性产出；初始给一笔起始光能，保证开局可以放下第一个产出单位。
- 光能上限存在上限值，防止无限囤积（数值见 §4.5 初始数值）。

### 4.2 布防单位（奥特曼阵营）
第一版提供 4 种单位，均为**定点放置、不移动**：

| 单位 | 造价（光能） | 冷却 | 作用 | 定位 |
| --- | --- | --- | --- | --- |
| 光能核心 | 50 | 短 | 每 X 秒产出光能 | 经济 |
| 光线射手 | 75 | 中 | 对本通道最前方的怪兽发射光线弹 | 主力输出 |
| 屏障战士 | 100 | 长 | 高生命值，阻挡怪兽推进 | 坦克 / 拖延 |
| 范围震荡 | 150 | 长 | 对本通道一定范围内的怪兽造成范围伤害 | 清场 |

- 放置规则：点击卡牌选中单位 → 防御带上的合法槽位高亮 → 点击槽位放置并扣除光能；已占用槽位不可放置。
- 冷却期间卡牌置灰，不可选择。

### 4.3 怪兽（敌方）
| 怪兽 | 生命值 | 速度 | 特性 |
| --- | --- | --- | --- |
| 小怪兽 | 低 | 中 | 数量多，基础推进 |
| 装甲怪兽 | 中 | 慢 | 减伤，需要持续输出 |
| 飞行怪兽 | 低 | 快 | 速度更快，考验前期布局 |

- 怪兽进入通道后向基地方向连续前进。
- 遇到**屏障战士**会停下并攻击（近战啃咬），被击破后继续前进。
- 光线射手 / 范围震荡对怪兽造成伤害，怪兽死亡后从场上移除。

### 4.4 波次（Waves）
- 第一版共 **3 波**，波次之间有一段准备时间（约 10 秒），顶栏显示「第 N / 3 波」与倒计时。
- 每波由若干「怪兽小队」按时间点陆续生成，波次越靠后数量与强度越高。
- 每波结束给出短暂提示，最后一波结束后进入胜利结算。

### 4.5 初始数值（第一版基线，可在评审时调整）
| 项目 | 数值 |
| --- | --- |
| 起始光能 | 100 |
| 光能上限 | 999 |
| 光能核心产出 | 25 / 8 秒 |
| 光线射手伤害 | 20 / 发，射速 1 发 / 1.2 秒 |
| 屏障战士生命 | 300 |
| 范围震荡伤害 | 40，半径内全部命中，冷却 6 秒 |
| 通道数 | 3 |
| 每条通道槽位数 | 5 |

### 4.6 渲染与循环
- 单页 `index.html` + Canvas 2D，`requestAnimationFrame` 驱动固定步长的逻辑更新（累加器方式），渲染与逻辑分离。
- 背景分层：天空 / 远景 / 通道地面 / 装饰物 / 单位 / 弹道 / UI。
- 哈希/坐标无关的随机只在初始化布局时用一次，保证每局地图观感稳定。

## 5. 胜负条件与操作

### 5.1 胜利条件
打完全部 3 波，且基地未被摧毁 → 显示「胜利」结算界面。

### 5.2 失败条件
任意怪兽抵达基地并造成一次突破（基地生命归零）→ 显示「失败」结算界面。
- 第一版基地生命设为 1 点突破即失败，或 3 点（待评审选择，默认 3 点更宽容）。

### 5.3 操作
| 操作 | 效果 |
| --- | --- |
| 鼠标点击 / 触屏点击卡牌 | 选中要放置的单位（显示造价与冷却） |
| 点击防御带高亮槽位 | 放置单位并扣除光能 |
| 再次点击已选卡牌 / 按 Esc | 取消选中 |
| 暂停按钮 / 空格键 | 暂停 / 继续 |
| 重新开始按钮 | 重置本局 |
| 结算界面按钮 | 重新开始 |

- 交互同时支持鼠标与触屏（pointer 事件），H5 移动端可玩。

## 6. 技术方案（H5）

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 运行形态 | 单个静态 `index.html`（+ 可选 `game.js` / `style.css`） | 无构建即可打开，满足「简版 H5」 |
| 渲染 | Canvas 2D | 轻量，适合 2D 塔防与特效 |
| 依赖 | 无第三方库 | 降低离线/加载风险 |
| 分辨率 | 逻辑坐标 960×540，等比缩放适配窗口 | 横屏体验，移动端自动缩放 |
| 状态管理 | 单一 `GameState` 对象（光能、波次、单位、怪兽、弹道、结果） | 逻辑简单可测 |
| 存档 | 第一版不做持久化 | 保持简版范围 |

> 以上文件位置（`index.html` 等）属于**后续实施步骤**，本步骤只交付本设计文档。

## 7. 实施计划（**待 Human 批准后执行**）

> ⚠️ 本节只是计划。在 Human 明确批准之前，不创建任何游戏源文件、不安装依赖、不生成构建产物。

1. **阶段 A：文档评审（当前）** — 交付 `docs/design.md`，等待 Human 对玩法、数值、胜负条件给出意见。
2. **阶段 B：骨架** — 创建 `index.html`（画布 + 顶栏 + 卡牌栏）、主循环、资源与波次状态机。
3. **阶段 C：地图与布防** — 生成 3 条曲线通道与槽位锚点、点击放置、光能消耗与冷却。
4. **阶段 D：战斗** — 怪兽生成与推进、阻挡判定、射手弹道与伤害、范围技能。
5. **阶段 E：胜负与打磨** — 结算界面、暂停/重开、移动端适配、基础特效与音效（可选）。
6. **阶段 F：验证** — 在浏览器打开自测：能放置、能产出、能击杀、3 波结束出胜利结算、突破出失败结算。

### 7.1 评审时希望 Human 确认的点
1. 通道数量 3 条是否合适（或改为 1 条单通道更简）。
2. 基地生命 1 点还是 3 点。
3. 单位数量 4 种是否够，是否需要「单体高伤」或「减速」类单位。
4. 是否接受纯代码绘制的原创简化造型（不使用影视素材）。
