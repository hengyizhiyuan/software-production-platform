## Architecture Lead decision boundary

The common G0/G4/ECF fault requires a contract for converting a Human-admitted semantic fact into a consumer-verifiable query **without changing the fact**, and an evidence rule separating source-checkable content from Product revision/provenance and lifecycle/authority effects. This crosses WIC/IRK, Verification and ECF ownership. The existing [static-context finding](architecture-finding-static-context-consumer-20261008.md) remains open. Two bounded choices require Architecture Lead selection:

1. **Pre-admission feedback:** publish a bounded consumer capability/unsupported-reason contract to WIC's existing structured-result repair before fact admission; revalidate the same Human source and exact value/scope/provenance. Verification must still fail closed if a later consumer differs. This needs an agreed capability response and ownership of the final admission check.
2. **Post-admission materialization:** preserve the immutable fact and have the appropriate Verification/ECF owner derive a candidate check plan with the fact ID, relation, value, scope and provenance; validate that plan against the original fact and exact target before checking the Git blob or governance record. This needs an agreed owner for plan validation and a rule for lifecycle evidence. It may not reinterpret Human Intent or silently drop unsupported facts.

Both choices must explicitly refuse missing/ambiguous source, conflicting facts, or absent Human authority. Neither authorizes a new global subject ontology, a second coordinator, an unbounded model loop, relaxed Context Budget, or automatic acceptance. **No cross-owner interface change is implemented pending this decision.**
