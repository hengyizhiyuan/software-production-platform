## 1. Closure conclusion

Watt does not adopt Spec-Driven Development as its Human-visible product
workflow. It absorbs selected SDD mechanisms into its own Motive-driven,
Reality-grounded software-production architecture.

Watt is not defined as:

```text
Prompt -> Requirements -> Design -> Tasks -> Code
```

Its approved direction is:

> Reality-grounded, progressively structured, Motive-driven production.

SDD is an important mechanism source, not Watt's top-level product paradigm.
No inspected framework establishes the complete Watt target of natural Motive
refinement, governed Work admission, Reality-driven Steering, independent
Verification, and trusted production while controlling Human cognitive cost
and structural return on investment.

## 2. Preserved Watt invariants

The synthesis preserves these existing invariants:

- Human defines intent. AI amplifies capability. System ensures trust.
- The first Human utterance is not Work.
- Conversation is provenance, not Product Truth.
- Work identity is Motive-bound.
- Asset, repository, application, and Project identity are not Work identity.
- Human Authority remains distinct from AI capability.
- Steering owns **WHAT NEXT**.
- Executor owns **HOW** inside admitted authority.
- Verification remains independently owned.
- Runtime Reality remains its own fact source.

No SDD, Pattern, Policy, artifact, or fast-response mechanism may silently
weaken these boundaries.

## 3. Progressive Structuring — approved

Human expression remains natural and initially open. Watt progressively
introduces only the structure that earns its cost.

```text
Human natural expression
    -> Open WIC
    -> Current Reality + Conversation provenance
    -> Evolving candidate understanding
    -> Tentative Pattern guidance
    -> Unknowns / assumptions / semantic obligations
    -> Focused refinement
    -> Next-step readiness
    -> Work Formation proposal
    -> Human Authority / Admission
    -> Governed Work Reality
```

The normative principle is **Minimum Sufficient Structure**. Every additional
layer, artifact, question, model call, gate, and ceremony must earn its keep.
Structure must not be demanded merely because a formal phase exists.

## 4. Adaptive Work Pattern guidance

Adaptive Work Pattern guidance is approved as an architecture direction:

> Pattern constrains the AI's search space, not the Human's expression space.

Pattern recognition may initially remain `OPEN`. A candidate Pattern may be
tentative, uncertain, reroutable, and eventually composable with other Pattern
mechanisms. Pattern depth should scale with ambiguity, risk, impact, and the
cost of being wrong. The Human should not normally need to select a workflow
type.

A Pattern primarily supplies semantic obligations and professional reasoning
guidance. It is not a rigid sequence of screens or steps, and it never becomes
a Truth owner or silently overrides Human Intent.

The following remain deferred: final taxonomy and count, persistence,
confidence calculation, blending, automatic switching, and UI representation.
Illustrative families in the
[Adaptive Work Patterns memo](../product/watt-adaptive-work-patterns-candidate.md)
remain candidate examples, not frozen domain values.

```text
PATTERN_GUIDANCE_DIRECTION
    APPROVED

PATTERN_TAXONOMY
    NOT_FROZEN

IMPLEMENTATION
    NOT_STARTED
```

## 5. Highest-decision-value refinement

“One question at a time” is not the fundamental architecture rule. Watt should
ask the question with the highest expected decision value.

Where safe, WIC should:

- infer reversible and low-risk detail;
- surface material assumptions;
- ask only high-value Human questions;
- stop refining when residual uncertainty is tolerable for the next governed
  step.

The goal is not zero ambiguity before movement. It is sufficient semantic
confidence for the next governed step. Human cognition should be reserved for
Motive, meaningful scope, irreversible decisions, major trade-offs, risk
acceptance, authority transfer, and materially ambiguous Product Intent. The
Human is not a repetitive form-filling or artifact-approval service.

## 6. Semantic, next-step-specific readiness

Readiness is semantic and next-step-specific:

```text
READY_FOR_NEXT_GOVERNED_STEP
    !=
WORK_FULLY_KNOWN
```

Future readiness may combine known facts, material unknowns, explicit
assumptions, risk, reversibility, Human Authority, required evidence, and
Pattern-specific semantic obligations. No algorithm or score is frozen.

A file, checkbox, or generated artifact may be a structural precondition. Its
existence is never sufficient semantic readiness.

## 7. Consumer-bound artifact lifecycle

> No production artifact without a named consumer or preserved obligation.

Artifacts should exist because they serve a Human decision, Steering,
Executor context, Verification obligation, recovery, historical rationale,
context selection, or scenario preservation—not because a process entered a
named phase or a template requires a file.

An artifact should materially improve at least one of intent clarity, decision
quality, implementation accuracy, Verification, risk reduction, traceability,
recovery, context efficiency, rework reduction, or Human cognitive efficiency.
Artifact lifecycle is consumer-bound rather than phase-bound.

This principle complements the
[Experience-before-Production candidate](../product/experience-before-production-candidate.md):
Patterns may guide whether and how deeply experience artifacts are useful, but
no universal artifact sequence is approved.

## 8. Layered Reality; no universal Spec Truth

Watt rejects `spec.md == Source of Truth`. It retains owner-specific Reality:

```text
Conversation     provenance
Interpretation   candidate
Work Reality     governed Work facts
Plan             direction
Repository       implementation Reality
Verification     verification Reality
Runtime          runtime Reality
```

Requirements, scenarios, designs, or future Spec projections may exist. They
do not automatically become a new authority owner, and layered Reality must
not collapse into one Markdown document.

## 9. Delta and revision semantics

New Human input, production discovery, or design correction should normally be
evaluated against existing governed Reality as a candidate delta:

```text
Current governed understanding
    + new Human input / Finding
    = Candidate Delta
```

The future representation should distinguish `ADDED`, `MODIFIED`, `REMOVED`,
`SUPERSEDED`, and unchanged obligations. Deterministic checks should protect
against represented semantic loss where possible, including scenario loss,
constraint loss, identifier coverage gaps, and stale references. Storage and
schema design remain open.

## 10. Brownfield Reality first

Existing documentation and historical specifications are evidence, not
automatically current truth. For brownfield Work:

```text
Repository / Runtime Reality
    first

Historical intent / specification / documentation
    evidence

Reconciliation
    before promotion into current governed understanding
```

Watt should not require exhaustive historical-document backfill without a
current consumer.

## 11. Intent-to-Verification lineage

Watt approves an explicit future relationship between represented intent and
Verification obligation:

```text
Intent / Requirement / Scenario revision
    -> Verification obligation
    -> exact implementation / Candidate revision
    -> Evidence
```

Textual path links alone are not a sufficient long-term lineage model, but no
identifier schema is frozen. Generic tests passing do not prove that Human
Intent was satisfied. Verification remains independently owned.

## 12. Production feedback authority — hard invariant

These are distinct events:

1. Repository or Runtime Reality reveals a new fact.
2. Current interpretation or design may need revision.
3. Human Motive or governed Work may or may not change.

Production discovery may create a `Finding` and a `Candidate Revision`; it
must not silently become new Human Intent.

```text
Production discovery
    -> Finding
    -> Candidate Reality / Intent Delta
    -> WIC / Steering / Human Governance
    -> Accepted Revision or Rejected Finding
    -> Continue
```

> Production Reality may challenge intent interpretation. It may not silently
> acquire Goal Authority.

## 13. WIC capability / behavioral Policy seam

A bounded architecture seam is approved:

```text
stable WIC capability code
    + versioned behavioral policy
```

Capability code owns Work identity, Human Authority, persistence, security,
immutable revision semantics, evidence capture, invariant enforcement, replay
isolation, and Provider transport capabilities.

A future behavioral Policy may configure Provider/model profile, interaction
instructions, question-selection strategy, Pattern guidance, readiness
strategy, context selection, assumption/explanation behavior, artifact
recommendations, and escalation thresholds.

Policy is behavior/configuration, not Product Truth. The seam is approved; the
final Policy schema, persistence, activation pointer, rollout, canary, shadow,
and production Policy service are deferred.

## 14. WIC Lab and evaluation

Replay, A/B comparison, ablation, Policy comparison, and benchmark execution
are supported as future directions. A full WIC Lab is not authorized.

```text
WIC_LAB
    CANDIDATE / DEFERRED

MINIMUM_REPLAY_CAPABILITY
    REQUIRED BEFORE OR WITH MAJOR WIC RECONSTRUCTION
```

Evaluation retains four separate layers:

- **WIC-Bench A:** Intent Understanding & Refinement;
- **WIC-Bench B:** Pattern & Readiness;
- **WIC-Bench C:** Specification / Experience Quality;
- **WIC-Bench D:** End-to-End Production Effectiveness.

These must not collapse into one aggregate score. Ground truth should use a
Human-adjudicated Reference Intent Package rather than the first Human message.
Future evaluation should cover Intent Fidelity, Human correction, invented
requirements, Work boundaries, Pattern/rerouting, readiness timing,
over-structuring, artifact ROI, Human cognitive cost, downstream rework,
Trusted Delivery Cost, and Human Perceived Intelligence.

## 15. OPEN_WIC baseline prerequisite

Before materially or destructively replacing current WIC behavior, Watt must
capture a bounded `OPEN_WIC_BASELINE`. The current behavior must not be
destroyed before it can be compared with the reconstruction.

The future baseline should preserve a small representative set of real Watt
dogfood cases, including Human input sequences, corrections, current
Work/Conversation context, model/provider/profile, WIC behavior revision,
resulting responses, and Work Formation outcome where applicable. Corpus and
harness implementation are outside this mission.

## 16. Fast Semantic Reception

Fast Semantic Reception is approved as an architecture direction. Watt should
respond quickly enough to feel attentive and intelligent even when deeper
reasoning continues.

```text
Time To First Meaningful Sentence
    !=
Time To Complete Response
```

Deep reasoning must not block the first meaningful Human feedback by default:

```text
Human Turn
    |-- Fast Semantic Reception Path
    |       -> immediate provisional understanding
    |       -> first meaningful sentence
    |
    `-- Deep WIC Path
            -> full Reality / Pattern / ambiguity / readiness reasoning
            -> continuation of the SAME Watt turn
```

The Human should experience one coherent Watt response, not two independent
agents. Fast reception is not a generic “received, processing” message. It
should truthfully communicate a small provisional semantic understanding such
as likely interaction kind, probable intent, relation to current Work,
confidence, or the first meaningful sentence.

**Fast is allowed. Fake is not.** Low confidence must be represented as
uncertainty rather than fabricated certainty.

## 17. Fast Path authority and context

Fast Path understanding is provisional and read-only. It must not independently:

- create or admit Work;
- mutate governed Work Reality;
- commit Human Intent;
- finalize a Pattern or declare semantic readiness;
- change Plan;
- authorize Production;
- make irreversible decisions.

The Fast Path should not require the full WIC context. A future small Fast
Context Card may include current Work identity, Motive summary, stage, recent
focus, latest Human/Watt turn, and a bounded set of high-value facts. This is a
context-shape candidate, not ECF design.

Low latency requires small high-value context rather than a lightweight model
combined with full context.

## 18. Model strategy and proportional compute

The first reconstruction strategy for Fast Semantic Reception is an external
lightweight/provider model, low-reasoning profile, and bounded context. The
goal is to test real latency and semantic accuracy without requiring
self-hosted inference.

```text
EXTERNAL_LIGHTWEIGHT_MODEL
    FIRST_IMPLEMENTATION_STRATEGY

SELF_HOSTED_OR_DISTILLED_RECEPTION_MODEL
    LONG_TERM
    DEFERRED
```

WIC must preserve a future substitution seam without selecting a model family,
size, accelerator, training pipeline, dataset, or deployment topology.

A future model cascade is possible but not frozen:

```text
Stage 0  deterministic routing / parsing where useful
Stage 1  Fast Semantic Reception
Stage 2  ordinary fast WIC reasoning
Stage 3  stronger reasoning when complexity warrants
```

Not every Human turn must traverse every stage. The guiding rule is
proportional compute.

## 19. Common-path latency guardrail

SDD or Pattern structure must not introduce a serial chain of model calls
before the first meaningful sentence. This is an architecture smell:

```text
Pattern classifier
    -> Requirements analyzer
    -> Conflict analyzer
    -> Readiness analyzer
    -> first user-visible sentence
```

Fast Semantic Reception should operate in parallel with deeper WIC reasoning
where safe. Structured analysis may continue after the first meaningful
sentence.

The approved experience metrics are:

- `TTFMS` — Time To First Meaningful Sentence;
- `TTCR` — Time To Complete Response;
- `TTCNS` — Time To Correct Next Step.

No one metric should be optimized while ignoring the others. The candidate
engineering target—not an achieved SLA—is:

```text
TTFMS
    P50 < 1 second
    P95 < 2 seconds
```

This must be validated against real Provider and runtime conditions. Semantic
accuracy has priority over meaningless speed. Quality measures must include
Semantic Receipt Accuracy, Human Correction Rate, False-confidence Rate,
meaningless/generic receipt rate, unnecessary verbosity, and TTFMS.

## 20. Structure ROI guardrail

Structure may increase local reasoning cost only when it reduces expected
downstream Human or production cost. A small refinement delay may be justified
if it avoids unnecessary Human turns; a larger pre-production analysis may be
justified if it prevents substantial wrong implementation. Repeated delay or
generated documents without measurable reductions in error, effort, or rework
are not justified.

Future WIC evaluation must measure this structural return on investment rather
than treating additional process as inherently safer.

## 21. Architecture drift smells

Future reviewers should treat these as architecture triggers:

```text
SDD == Watt product paradigm
Requirements -> Design -> Tasks == Work lifecycle
first Human message == ground truth
first message -> permanent Pattern
Pattern == user-selected workflow mode
file exists == semantic readiness
artifact created because phase requires it
spec.md == universal Truth
repository == Human Intent
Executor discovered fact == Human changed Motive
generic test PASS == intent satisfaction
Human approves every generated artifact
full WIC context required before first sentence
serial model calls before first meaningful response
fast response == fake acknowledgement
Fast Path mutates Work Reality
self-hosted small model required for current release
```

## 22. Intentionally deferred design

The following remain open or deferred:

- final Pattern taxonomy, persistence, confidence, blending, switching, and UI;
- exact readiness algorithm;
- Spec/domain schema and exact artifact types;
- full WIC Policy schema, activation, rollback, shadow, and canary;
- full WIC Lab;
- benchmark case count, scoring, and commercial experimentation;
- ECF;
- self-hosted or distilled reception model;
- production model cascade implementation.

They must not be inferred as implementation-ready from this closure.
